# 08. Godot как источник кадров: замкнутый цикл «камера очков → ядро → голограмма»

Контекст: `godot/README_GODOT.md`, `godot/scripts/main.gd`, `godot/scripts/sim_rig.gd`, `core/arcore/hal.py`,
`docs/02_hal_contracts.md`.

Задача:
1. В Godot: второй SubViewport «камера очков RGB» (слой реальности, параметры камеры из конфига промпта 01, 1280×720),
   жёстко закреплённый на голове со смещением камера↔глаз (из конфига). Кадры — JPEG по UDP на :47102 (заголовок:
   t_ns, номер куска; кадр режется на куски ≤ 60 КБ) **или** через v4l2loopback (`setup/ubuntu/05_v4l2loopback.sh`, ffmpeg).
2. В ядре: `rigs/godot_frames.py` — FrameSource, собирает кадры из UDP; PoseSource — из сообщений `head`
   (истина для оценки). `AR_RIG=godot`.
3. В клиенте: `--use-anchor` ставит голограммы по `anchor` от ядра. Добавить отладочный слой: истина сцены (тонкая рамка)
   против позы ядра (голограмма) и число «смещение, мм» в углу.
4. `make sim` запускает режим godot; `make sim-cli` остаётся на синтетике Python.

Критерии приёмки: на верстаке 040 в Godot смещение голограммы относительно истины ≤ 3 мм медиана при стоящей голове и
≤ 8 мм при повороте головы 60°/с; задержка «кадр → anchor» ≤ 50 мс на ПК с GPU; тест ядра на записанных кадрах Godot.
