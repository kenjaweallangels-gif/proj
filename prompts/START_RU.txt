Стартовый текст для ведущего кодирующего агента (Claude Code / Codex / Cursor) — Echo Runtime, ветка исследования
==================================================================================================================

Ты продолжаешь прототип Echo Runtime игры «Нулевое эхо» на ПК владельца (RTX 3060 12 GB, 32 GB RAM, Ubuntu).
Источник требований: docs/source/ZERO_ECHO_Engine_LocalAI_API_RU.html (§1–§23). Контракты модулей: docs/SPEC.md.
Текущий статус каждого направления: reports/validation.json. Не повторяй уже сделанное — сначала прочитай README.md.

Главный принцип: модель предлагает → Intent Authority (core/) проверяет → мир меняется только после принятия
и фактического выполнения задачи. Игра полностью работает без модели и без сети.

Порядок работы (Документ §20, §22):
  1. E0 — стенд. Запусти `python3 tools/hw_manifest.py`, открой tools/webgpu_probe.html в целевом браузере
     (Chrome/Chromium с актуальным драйвером NVIDIA), сохрани JSON. Впиши точный CPU, драйвер, Wayland/X11,
     частоту монитора, режим питания. Ничего не придумывай: неизвестное = null.
  2. Сборка: `tools/build_all.sh` (нужны g++/clang, cmake, ninja, Node ≥22.18, Emscripten для WASM).
     Проверки: `tools/test_all.sh` → reports/validation.json.
  3. Контрольный маршрут: `node tools/serve.mjs web/dist 8000`, открыть http://127.0.0.1:8000/ → вкладка
     «Метрики» → «Контрольный маршрут». Для приёмки: 3 прогретых прохода по 10 минут, без генерации кадров,
     фиксированный render scale. Сохрани RouteReport JSON и видео. Только эти данные на RTX 3060 — замер.
  4. Локальная модель: llama.cpp (CUDA и CPU), Qwen3-1.7B Q4 (режим без рассуждений через chat template).
     Маршрут local_llamacpp в data/providers.example.json → запусти шлюз `node gateway/src/server.ts
     --config <твой конфиг>` → провайдер «Шлюз» в UI. Затем совместный прогон: рендер + одна генерация.
     GPU-генерация допускается только после калибровки (пороги в data/profiles.json → admission.gpu_gate).
  5. Внешние API: ключи только на сервере шлюза (env ECHO_KEY_<ROUTE> или файл секретов 0600), никогда в
     клиенте. `node eval/run.ts --provider gateway:<url>:<route>` на 100 сценах → отчёт качество / p95 / цена часа.

Правила для каждой задачи (Документ §20):
  - Конкретные входы, разрешённые файлы, один измеримый результат, способ проверки, лимит повторов,
    список непроверенного.
  - Машиночитаемый результат: pass / fail / blocked / not_run, git revision, версии зависимостей.
  - Модели, драйверы и платные API не устанавливаются и не оплачиваются молча.
  - Тесты контракта выполняются без ключей и без внешних запросов.
  - Нельзя называть capability probe, SwiftShader-рендер или unit-тест доказательством 60 FPS.
  - Нельзя ослаблять Intent Authority ради «живости»: число допущенных нарушений должно оставаться 0.

Ближайшие задачи (по приоритету):
  a) Замер контрольного маршрута W60/N60 на RTX 3060 (браузер) и совместный trace с llama.cpp (Nsight Systems).
  b) Порт рендера на C++ (webgpu.h) с Dawn native + Emdawnwebgpu — шейдеры WGSL уже общие (web/src/shaders).
  c) Реальные ассеты: Blender → glTF → meshoptimizer/KTX2 cooker, chunk manifest, бюджет texture pool.
  d) Сравнение локальной модели и одного внешнего API на data/eval/scenes_ru.json.
  e) Decision gate после E2/E3 (Документ §20): ≥20% по p95 GPU или ≥25% по resident memory при сопоставимом
     изображении против UE D0 — либо требуемый браузерный выпуск. Иначе UE остаётся основной native-веткой.
