# Правила для ИИ-ассистента (AGENTS.md)

Этот файл читают Cursor, Claude Code, Codex, Aider и другие агенты. Следуй ему в каждой сессии.

## Проект в двух словах
Система пошаговой AR-сборки интерьеров пассажирских ВС. Очки (пилот: VITURE Luma Ultra) накладывают 3D-модель
сборки на реальное изделие, ведут по шагам ТП, слушают голос, показывают КД и чат, пишут журнал на сервер цеха по Wi-Fi.
До покупки очков всё разрабатывается и тестируется на **симуляторе очков** (pkg1) и в **веб-демо** (pkg2).

## Главные правила
1. **Сначала читай контракты.** `docs/02_hal_contracts.md` (интерфейсы железа) и `docs/03_data_model.md` (формат операции).
   Не меняй их без явной просьбы. Если изменение нужно — предложи его отдельным сообщением.
2. **Не выдумывай API.** Для VITURE SDK, Godot, OpenCV, Vosk сверяйся с документацией в `docs/` и `vendor/` (если есть)
   или с официальной документацией. Если не уверен в сигнатуре — напиши заглушку с TODO и вопросом, а не догадку.
3. **Маленькие срезы.** Одна задача = один промпт из `*/prompts/`. Не делай работу следующих промптов заранее.
4. **Тесты обязательны.** Любая логика (трекинг, шаги, разбор пакета, сервер) — с тестом. Работа не закончена,
   пока `make test` (pkg1) или `npm test` (pkg2) не зелёные. Запускай их сам.
5. **Текстовые форматы.** Сцены Godot (`.tscn`), JSON, YAML, CSV. Не создавай бинарных сцен.
6. **Единицы:** миллиметры в данных и в ТП, метры внутри 3D-движков. Конвертируй на границе (`io/package.py`, `src/engine/package.js`).
   Ось Y — вверх. Поворот — кватернион `[x, y, z, w]`.
7. **Офлайн.** Никаких облачных сервисов: распознавание речи локально (Vosk), сервер в сети цеха, без телеметрии наружу.
   Единственное исключение — веб-демо для показа: кнопка «Голос» там использует Web Speech API браузера (облако), шрифты —
   Google Fonts с запасным системным шрифтом. В ПО очков и сервера так нельзя.
8. **ИБ.** Кадры камеры обрабатываются на устройстве и не сохраняются. Фото — только по явной команде и только в журнал на сервер.
9. **Лицензии.** Только MIT, BSD, Apache-2.0, LGPL (динамически), PostgreSQL. Не подключай Unity, Vuforia и GPL-библиотеки
   в клиент без согласования. GPL-инструменты допустимы только как отдельные утилиты сервера (например, `pdftoppm`).
10. **Язык.** Интерфейс, сообщения, комментарии к бизнес-логике — по-русски. Имена в коде — по-английски.
11. **Коммиты** после каждого зелёного шага, сообщение: `pkgN: что сделано`.

## Как запускать
- Первый раз на ПК: Windows — `powershell -ExecutionPolicy Bypass -File scripts\setup.ps1`, Linux/mac/WSL — `bash scripts/setup.sh`
  (`--full` / `-Full` — полный набор pkg1: сервер, CAD, голос).
- pkg1: `cd pkg1-sim-vm && make venv && make test` · сервер: `make server` · симулятор: `make sim`
  (на Windows без WSL: `.venv\Scripts\python -m pytest -q tests` при `PYTHONPATH=core;.;tools`)
- pkg2: `cd pkg2-demo-web && npm install && npm run dev` · тесты: `npm test` · браузерный тест: `npm run build && npm run smoke`
- Стенд очков: `make lab-detect | lab-pose-demo | lab-pose SRC=viture | lab-record | lab-analyze DEVICE=… | lab-camera CAM=…`
  (Windows: `scripts\lab.ps1 detect | pose-demo | pose | record | analyze | camera`), страница `pkg2-demo-web/lab.html`.
- Симулятор с головой в реальных очках: `galley.html?pose=1` (мост позы `tools/glasses_lab/pose_bridge.py`).

## Git
- Работай в ветке задачи, коммит после каждого зелёного шага (п. 11), `git push`, затем PR в `main`.
- Не коммить: `vendor/` (SDK очков — закрытые лицензии), записи сеансов `rec/`, реальные модели и КД (`data/real/`).
