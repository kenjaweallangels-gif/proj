# 04. Конвейер: 3D-модели из NX, листы КД, техпроцесс

Цель: из реальных данных изделия (3D-сборка в NX, КД в PDF, ТП в Excel/ЛОЦМАН/САПР ТП) получить пакет операции,
который одинаково работает в демо, симуляторе и на очках.

```
NX сборка ──STEP AP242──> step_to_glb.py ──GLB (узлы = ID деталей)──┐
КД (PDF) ──pdftoppm──> PNG листов ──(разметка позиций)──────────────┤
ТП (Excel) ──CSV: operation/markers/parts/fasteners/steps──> tp_csv_to_json.py ──> пакет JSON
                                                         validate_bom.py ──> отчёт расхождений
```

## 1. 3D-модель из NX
1. В сборке NX оставьте только то, что видит сборщик на операции: устанавливаемые детали, ответные базы (ложемент, шпангоуты
   в зоне операции), крепёж — по желанию (крепёж проще рисовать примитивами из пакета).
2. Назовите компоненты по правилу: **имя компонента = ID детали в пакете** (`K204`, `K3140_L`, `PB12`). Латиница, цифры, `_`.
   Кириллица в STEP кодируется `\X2\` и часто теряется — не полагайтесь на неё.
3. СК сборки = СК операции: начало в базе (центр ложемента или ось секции на шпангоуте), Y вверх. Если в NX Z вверх —
   поверните при экспорте или задайте `--up z` в конвертере.
4. File → Export → STEP, протокол **AP242**, сохранять структуру сборки, единицы мм.
5. Конвертация: `python tools/step_to_glb.py input.step models/op040_shelf.glb --deflection 0.3 --up y`
   (cascadio на базе OpenCascade; запасной путь — FreeCAD `Import`→`Export glTF`).
   `--dump-poses poses.csv` выгрузит центры узлов в мм — из них удобно заполнить `tx;ty;tz` в `parts.csv`.
6. Оптимизация (Node.js): `gltf-transform optimize in.glb out.glb --compress meshopt --texture-compress false --flatten false --join false --simplify false`
   (по умолчанию `optimize` сливает узлы и упрощает сетку — детали потеряют имена; флаги проверены на gltf-transform 4.5).
   Цель: < 5 МБ на операцию, < 200 тыс. треугольников.
7. Проверка: `python tools/validate_bom.py пакет.json models/op040_shelf.glb --tol-mm 2` — каждый `parts.node` есть в GLB,
   центр узла совпадает с `target.position` в пределах 2 мм.

Единицы и оси (проверено тестом `pkg1-sim-vm/tests/test_step_to_glb.py`): cascadio сам переводит мм в метры, а оси
оставляет как в CAD. При `--up z` точка CAD (x, y, z) мм попадает в GLB как (x, z, −y) м — это и есть Y-вверх.

Если у вас есть модуль NX Extended Reality, можно экспортировать glTF прямо из NX — правила имён те же.

## 2. Листы КД
1. `bash tools/kd_pdf_to_png.sh КД.pdf kd/ 200` — PNG 200 dpi по листам (нужен `poppler-utils`).
2. Позиции на листе (для подсветки): в `kd_sheets.csv` колонка `positions` — JSON `{"1": [x, y, w, h], ...}` в пикселях PNG.
   Быстро разметить можно в любом редакторе изображений; позже — инструментом в консоли технолога.
3. На очках лист показывается в негативе (светлые линии на тёмном): на прозрачном дисплее белый фон слепит.

## 3. Техпроцесс → шаги
Технолог заполняет 6 таблиц (Excel, сохранить как CSV UTF-8, разделитель `;`). Пример: `data/examples/op040_csv/`.

| Файл | Строка = | Ключевые колонки |
|---|---|---|
| operation.csv | параметр операции | id, title, product, revision, workplace, units, reference_frame, model_id, model_uri, model_note, check_from/to/nominal_mm/tol_mm |
| markers.csv | метка привязки | id, dictionary, size_mm, x y z, qx qy qz qw |
| parts.csv | деталь | id, designation, name, node, tx ty tz, qx qy qz qw, source_*, kd_sheet, kd_pos, mass_kg |
| fasteners.csv | крепёж | id, type, designation, part, x y z, ax ay az, torque_nm, lock, new_only |
| steps.csv | переход ТП | n, id, title, kind, parts, fasteners, tool, torque_nm, check_*, critical, confirm, norm_s, kd, notes |
| kd_sheets.csv | лист КД | id, uri, title, positions |

Сборка пакета (из корня репозитория): `python pkg1-sim-vm/tools/tp_csv_to_json.py data/examples/op040_csv out/op040.json`
— с проверкой по JSON Schema и ссылок шаг → деталь/крепёж/лист. Пример CSV собирается в JSON, совпадающий по содержимому с
`data/examples/op040_shelf_bench.json` (тест `test_tp_csv.py`). Пустая ячейка = поле не задано, десятичная запятая допустима.

### Откуда брать координаты
- `target` детали — из сборки NX (положение компонента). Скрипт `step_to_glb.py --dump-poses poses.csv` выгружает позы узлов
  в мм (центры габаритов узлов), их можно вставить в parts.csv.
- Крепёж — центры отверстий из модели; ось — нормаль к поверхности. Для начала хватает ручного ввода по КД.
- Метки — по факту установки на оснастку/шпангоут. Позицию метки измеряют один раз (калибровка рабочего места)
  или ставят метки в фиксированные гнёзда оснастки, заложенные в её КД.

## 4. Привязка к реальности
- На верстаке: 4 метки на ложементе в известных местах (гнёзда в оснастке).
- В фюзеляже: метки на струбцинах на шпангоутах зоны + на рельсах пола. Позицию струбцин фиксирует шаблон.
- Контрольное расстояние (`check_distance`) проверяет масштаб: если реальное расстояние между метками отличается от
  номинала больше допуска — система не начинает операцию (неверная оснастка, ревизия или метка сбита).
