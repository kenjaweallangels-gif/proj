# 01. Архитектура

## Цель
Сборщик в очках видит следующий шаг сборки прямо на изделии: какая деталь, откуда взять, куда поставить,
каким крепежом и с каким моментом. Подтверждает шаг голосом. Технолог, мастер и ОТК видят ход работы и отвечают в чате,
привязанном к шагу. Всё работает в сети цеха без облака.

## Принцип: одно ядро, разные источники и экраны

```
             ┌──────────── Источники (HAL) ────────────┐
             │ SimRig     ReplayRig     VitureRig  ...  │   кадры камеры, поза 6DoF, IMU, звук
             └───────────────┬─────────────────────────┘
                             ▼
 ┌──────────────────── Ядро (Python, pkg1/core/arcore) ────────────────────┐
 │ tracking: метки ArUco/AprilTag → поза изделия; проверка масштаба          │
 │ steps:    машина состояний операции; журнал; таймеры                      │
 │ voice:    Vosk (грамматика команд) + VAD                                  │
 │ io:       пакет операции (JSON), кэш, синхронизация с сервером            │
 └───────────────┬─────────────────────────────────────┬────────────────────┘
                 │ UDP JSON (поза, шаг, события)        │ HTTP/WebSocket
                 ▼                                      ▼
 ┌──────── Клиент отображения ────────┐      ┌──────── Сервер цеха ────────┐
 │ Godot 4 (очки, ПК)                  │      │ FastAPI + PostgreSQL         │
 │ или веб-демо Three.js (pkg2)        │      │ пакеты операций, GLB, КД     │
 │ голограммы, HUD, КД, чат            │      │ журнал, чат по шагам         │
 └─────────────────────────────────────┘      │ консоль технолога (веб)      │
                                              └──────────────────────────────┘
```

- **HAL** (Hardware Abstraction Layer) — единственное место, где код знает про конкретное железо.
  Ядро получает `Frame`, `Pose6D`, `PCM16` одинаково от симулятора, записи или очков. Подробно: `02_hal_contracts.md`.
- **Ядро** не зависит от движка отображения. Его можно гонять в тестах без окна.
- **Клиент** только рисует: получает позу изделия и состояние шага, показывает голограммы и панели.
- **Сервер** хранит истину: пакеты операций, модели, листы КД, журнал выполнения, чат.

## Режимы работы

| Режим | Источник | Клиент | Зачем |
|---|---|---|---|
| `sim` | SimRig (синтетические кадры с известной позой) | Godot или окно OpenCV | Разработка и автотесты без очков |
| `replay` | Записи сеансов в формате EuRoC | без окна | Регрессия на реальных данных цеха |
| `viture` | VITURE XR Glasses SDK: UVC-камера + 6DoF | Godot на Linux-ПК / Neckband | Пилот |
| `demo` | нет (скрипт камеры) | веб, pkg2 | Показ и обучение |

## Потоки данных одного шага
1. Клиент запрашивает у сервера пакет операции и кэширует его (JSON + GLB + PNG листов КД).
2. Ядро находит метки, считает позу ложемента/шпангоутов, проверяет масштаб по контрольному расстоянию.
3. Движок шагов публикует текущий шаг; клиент анимирует голограмму детали и крепежа.
4. Голос «Сборка, дальше» → ядро проверяет условия шага (критичный? нужен ввод момента? фото?) → журнал → следующий шаг.
5. Журнал и сообщения уходят на сервер; при обрыве Wi-Fi копятся локально и досылаются.

## Стек
| Слой | Инструмент | Лицензия |
|---|---|---|
| Ядро | Python 3.12, OpenCV 4.x (contrib), NumPy, Vosk | Apache-2.0 / BSD |
| Клиент очков | Godot 4.7, GDScript | MIT |
| Веб-демо | Vite, Three.js | MIT |
| Сервер | FastAPI, SQLAlchemy, PostgreSQL 16 (SQLite для разработки) | MIT / PostgreSQL |
| CAD → 3D | NX → STEP AP242 → cascadio/FreeCAD → GLB → gltf-transform | MIT / LGPL |
| КД | PDF → PNG (`pdftoppm`) на сервере | GPL, как отдельная утилита |

Почему не Unity: Unity приостановил работу с Россией (03.2022), бесплатная лицензия ограничена выручкой $200 тыс.
Почему не Vuforia: PTC ушла из России (03.2022).
