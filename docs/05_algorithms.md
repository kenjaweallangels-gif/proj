# 05. Алгоритмы

## 1. Привязка (трекинг меток)
Вход: `Frame` (BGR, K, dist), список меток операции. Выход: поза СК операции в СК камеры + качество.

1. `cv2.aruco.ArucoDetector(dictionary, DetectorParameters)` с `cornerRefinementMethod = CORNER_REFINE_SUBPIX`.
2. Для каждой найденной метки из пакета — 4 угла в СК операции (из `pose` метки и `size_mm`) ↔ 4 угла на изображении.
3. Все соответствия всех меток → `cv2.solvePnP(..., flags=SOLVEPNP_ITERATIVE)` (начальное приближение — `SOLVEPNP_SQPNP`).
   Для одной метки — `SOLVEPNP_IPPE_SQUARE`.
4. Ошибка репроекции в пикселях → качество. Отбрасывать решение, если ошибка > 2 px или найдено < 2 меток.
5. Сглаживание: экспоненциальный фильтр по позиции и SLERP по повороту, α зависит от качества.
6. Между обнаружениями позу держит 6DoF очков: `T_world_op = T_world_cam(t) · T_cam_op`. Метки поправляют дрейф раз в 0,5–1 с.

Ожидаемая точность (оценка): калиброванная камера 1080p, метки 80–100 мм на 0,4–1 м — 1–3 мм в плоскости, 3–10 мм по глубине
для одной метки; плата из 4 меток заметно лучше. Видимое смещение на оптическом дисплее больше (5–15 мм) из-за калибровки
«камера ↔ дисплей». Это нужно измерять на пилоте.

## 2. Проверка масштаба и ревизии
- По найденной позе считаем положение двух точек `check_distance` и сравниваем с номиналом.
- Дополнительно: по 3+ меткам считаем масштаб Umeyama (SVD, `tracking/registration.py: ScaleMonitor`) — если масштаб ≠ 1 ± 3 %,
  значит неверный размер печати меток или не та оснастка. Решение — по медиане за 15 кадров: в одном кадре расстояния между
  центрами одиночных меток 80 мм на 0,7 м гуляют на 10–25 мм (замер на синтетике), а медиана масштаба держится в 1 ± 1 %.

## 3. Движок шагов (машина состояний)
```
IDLE → LOADING → ALIGNING → SHOWING ⇄ WAITING → (VALUE_INPUT | PHOTO) → LOGGED → SHOWING(next) … → CHECK → DONE
                    │ метки не найдены 20 с → MANUAL_ALIGN (3 точки) → SHOWING
```
- Команды: `next, prev, repeat, slower, faster, kd, chat, panel, ok, reject, value:<число>`.
- `critical=true` или `confirm in (value, photo)` — `next` не переводит шаг, пока не введено значение/не сделано фото.
- Каждое событие → запись журнала: время, шаг, команда, значения, качество привязки.
- Норма времени `norm_s`: превышение ×1,5 — событие мастеру в чат.

## 4. Голос
- Vosk `vosk-model-small-ru-0.22` (45 МБ, Apache-2.0) в режиме грамматики: список фраз + `[unk]`.
- Ключевое слово «сборка» перед командой; детектор речи (VAD) — Silero или webrtcvad, чтобы не слушать шум постоянно.
- Словарь команд и синонимы — `core/arcore/voice/commands.py`. Числа для ввода момента/зазора: «три и две», «шесть восемь».
- Запасной ввод: кнопка на очках/кольце/планшете, жест.

## 5. Анимация шага
Из пакета: деталь (узел GLB или примитив), её `source` и `target`. Фазы прогресса 0..1:
- 0–0,08 подсветка места взятия; 0,08–0,32 голограмма летит по дуге (высота 0,25 м) к месту; 0,32–0,42 посадка и угасание;
- 0,42–0,86 работа сборщика (в демо — анимация рук); 0,86–1 крепёж входит вдоль `axis` с вращением.
- Голограмма: контур (рёбра, порог 22°) + слабая заливка, аддитивно, без записи глубины.

## 6. Окно дисплея
На очках с окном 52° крупные детали не помещаются. Правила интерфейса:
- в окне — один узел/крепёж за раз; деталь целиком — контуром, если сборщик отошёл;
- стрелка у края окна на цель вне окна;
- КД и чат — панели в пространстве сбоку, открываются поворотом головы; HUD — в углу окна, сворачивается через 5 с.
