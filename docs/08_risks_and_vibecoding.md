# 08. Риски и правила разработки с ИИ

## Риски
| Риск | Мера |
|---|---|
| SDK VITURE не выдадут или ограничат | Запрос на 1-й неделе. HAL позволяет заменить очки (Rokid, Pico, планшет, проектор) |
| Точность наложения хуже ожиданий | Обещать ≈1 см, плата меток на базах изделия, калибровка дисплея, измерение на пилоте |
| Разрыв «симулятор → реальность» | Помехи в синтетике, ранние записи с очков, те же тесты на записях |
| Узкое окно дисплея (52°) в фюзеляже | Интерфейс под окно; для крупных узлов — лазерная или видеопроекция |
| Шум цеха | Ключевое слово, грамматика, гарнитура, кнопка |
| ИБ и камера | Кадры только на устройстве, фото по команде, сервер в контуре цеха |
| Лицензии (Unity, Vuforia, NX XR) | Стек MIT/Apache; STEP вместо прямого glTF из NX |
| ИИ выдумывает API | Документация SDK в `vendor/`, тесты на каждую функцию, заглушки с TODO |

## Правила вайбкодинга
1. Одна задача — один промпт из `prompts/`. Перед началом ассистент перечисляет файлы, которые изменит.
2. Сначала тест, потом код. Ассистент сам запускает тесты и показывает вывод.
3. Не принимайте изменения контрактов (`docs/02`, `docs/03`, `schemas/`) «между делом».
4. Коммит после каждого зелёного шага. Если ассистент «ушёл не туда» — откат, а не исправление поверх.
5. Документация SDK и примеры кладутся в `vendor/<sdk>/` — ассистент обязан сверяться с ними.
6. Раз в неделю — обзор архитектуры: попросите ассистента сравнить код с `docs/01_architecture.md` и перечислить расхождения.
7. Крупные файлы > 400 строк — повод разделить модуль.
8. Записи сеансов с очков — главный актив: каждая становится регрессионным тестом.
