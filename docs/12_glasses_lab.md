# 12. Стенд очков: что делать, когда очки приедут

Цель — за 2–3 дня измерить реальные характеристики двух комплектов (VITURE Luma Ultra + Pro Neckband,
XREAL One Pro + Eye + Beam Pro), подставить их в симулятор вместо оценок и проверить, что наше ПО работает с очками.
Инструменты уже в репозитории:

| Что | Где | Без SDK |
|---|---|---|
| Найти очки на USB, как монитор, камеры | `pkg1-sim-vm/tools/glasses_lab/detect.py` · `make lab-detect` · `scripts\lab.ps1 detect` | да |
| Тестовые картинки на дисплее очков | `pkg2-demo-web/lab.html` (поле, резкость, читаемость, яркость, цвет, стерео, задержка, поза головы) | да |
| Поза головы → симулятор и стенд | `glasses_lab/pose_bridge.py` (WebSocket :47110) · `galley.html?pose=1` · `lab.html` → «Поза головы» | только `demo`/`replay` |
| Запись позы и анализ дрейфа и шума | `pose_bridge.py --record` + `imu_analyze.py` · `make lab-record`, `make lab-analyze` | нужен источник позы |
| Камера очков: частота кадров, метки ArUco | `glasses_lab/camera_check.py` · `make lab-camera CAM=1` | да (VITURE RGB — UVC) |
| Замеры → профили симулятора | `pkg2-demo-web/measurements/<id-модели>.json` (пример — `_example.json`) | да |

## Что подготовить

- ПК: Windows 10/11 или Linux. Порт USB-C с DisplayPort Alt Mode: на ноутбуке он помечен значком DP или Thunderbolt. Если такого порта нет, нужен адаптер
  HDMI → USB-C от производителя очков.
- Браузер Chrome или Edge (полноэкранный режим на втором мониторе).
- Телефон со съёмкой 240 к/с (slow-mo) — для задержки.
- Люксметр (желательно) — для яркости и пропускания. Весы на 200 г.
- Метки стапеля, распечатанные в масштабе 1:1: `cd pkg1-sim-vm && make markers`. Масштаб проверить линейкой.
- Установленный проект: `scripts/setup.ps1` (Windows) или `bash scripts/setup.sh` (Linux/mac), см. README.

## День 1 — штатный режим, обе модели, без SDK

1. **Подключение.** `scripts\lab.ps1 detect` (или `make lab-detect`).
   - Должно появиться `✓ VITURE …` или `✓ XREAL …` и второй монитор 1920×1080/1200.
   - VID XREAL в `detect.py` взят из открытых драйверов: если очки не нашлись, сверьте VID в диспетчере устройств и поправьте `KNOWN_VIDS`.
2. **Стенд на экране очков.** `cd pkg2-demo-web && npm run dev` → откройте `http://localhost:5173/lab.html`, нажмите
   «На экран очков» (или перетащите окно на монитор очков и нажмите F). D — выбрать модель.
   - **Поле.** На какой градусной отметке обрезается картинка по краям. Записать `fovDiag`: диагональ = √(ш² + в²) по углам.
   - **Резкость.** Решётки в центре и по углам. Где 1-пиксельные линии сливаются — зона мыла (отметить в notes).
   - **Читаемость.** Самая мелкая строка, читаемая без напряжения, в градусах. Это минимальный шрифт окон КД. Сравнить с симулятором.
   - **Яркость.** Белое поле, уровень 9 (Shift+9 — 100 %). Люксметр прижать к линзе на месте глаза → E, лк.
     Яркость L = E / Ω, где Ω — телесный угол окна: Ω = 4·asin(sin(ш/2)·sin(в/2)).
     Пример: окно 45×29° → Ω ≈ 0,383 ср; E = 500 лк → L ≈ 1300 нит. Это `nits`.
   - **Пропускание линз.** Чёрное поле (уровень 0). Люксметр на месте глаза без очков, затем за линзой: `transmit` = E за линзой / E без очков.
     Повторить на каждой ступени затемнения (в notes).
   - **Стерео.** Включить 3D кнопкой на очках, монитор станет 3840×… Л и П должны быть у своих глаз; кольца «ближе/дальше» сливаются.
   - **Задержка и частота.** Сделать зеркало экрана (Win+P → «Повторяющийся») и снять телефоном в slow-mo монитор и очки вместе.
     Разница счётчиков кадров × интервал кадра = задержка вывода. `refresh` — частота на экране стенда.
   - **Штатный якорь XREAL (чип X1).** Режим Anchor. Снять через линзу резкий поворот головы на фоне неподвижного предмета.
     Число кадров slow-mo до сдвига картинки × 4,2 мс = `latencyMs` штатного режима.
3. **Вес** очков на весах → `weightG`.
4. **Замеры в файл.** На стенде нажмите M, впишите значения и скачайте `<модель>.json` в `pkg2-demo-web/measurements/`.
   Перезапустите `npm run dev`. В карточке «Очки» симулятора появится строка «Измерено …», и симулятор будет считать по реальным значениям.
5. **Сравнение в симуляторе.** Откройте `galley.html` с той же моделью и сравните окна КД, читаемость и яркость в цеху
   с тем, что видно в очках. Расхождения записать в `docs/09_hardware_glasses.md`.

## День 2 — своё ПО: VITURE на ПК

1. **SDK.** Получите VITURE XR Glasses SDK (C) в программе разработчиков и положите заголовки и библиотеку в
   `pkg1-sim-vm/vendor/viture/` (в git не попадает). Дальше — `pkg1-sim-vm/prompts/11_viture_rig.md`.
   Имена функций берутся **только из заголовков** (AGENTS.md, п. 2). Из открытой документации известны:
   - поза 6DoF с упреждением;
   - режимы 2D/SBS;
   - 9 ступеней яркости;
   - затемнение;
   - камеры RGB (UVC) и стереокамеры трекинга.

   Всё это нужно сверить с заголовками.
2. **Источник позы.** Реализовать `VitureSource.read()` в `glasses_lab/pose_bridge.py` через обёртку из prompts/11.
   Затем `make lab-pose SRC=viture` → `lab.html` → «Поза головы»: сетка должна стоять в мире при поворотах головы.
   Симулятор с реальной головой: `galley.html?pose=1`.
3. **Дрейф и шум.**
   - Положите очки неподвижно на 5 минут и запишите позу: `make lab-record SRC=viture`.
   - Проанализируйте запись: `make lab-analyze DEVICE=viture-luma-ultra`.
   - В замеры попадут `imuHz`, `driftDegMin`, `poseNoiseDeg`.
4. **Камера и метки.** `make lab-camera CAM=<индекс RGB-камеры очков>` с метками стапеля в кадре: должно быть ≈ 30 к/с и найдены ID меток.
5. **Привязка к изделию.** Калибровка «камера ↔ дисплей» и проверка смещения голограммы ≤ 10 мм на 0,6 м — prompts/11, п. 3.
6. **Своё ПО в замеры.** Задержку нашего клиента (`sdk.latencyMs`), частоту (`sdk.hz`) и дрожание позы (`sdk.trackMM`, `sdk.trackDeg`)
   внести формой стенда (M) — раздел «Своё ПО».

## XREAL на ПК и Beam Pro

- На ПК XREAL работает как монитор: весь День 1 проходится так же.
- Позу на Linux можно читать через XRLinuxDriver: только 3DoF, драйвер под GPL, поэтому подключается отдельной программой.
  Источник `xrlinux` в `pose_bridge.py` — заглушка: формат вывода берётся из документации драйвера (prompts/12, шаг 4).
- 6DoF с камерой Eye — только через XREAL SDK 3.1 (Unity) на Beam Pro. По AGENTS.md, п. 9, Unity в клиенте — только по согласованию.
  До решения проверяем XREAL в штатном режиме, а 6DoF — встроенным якорем X1 с Eye.

## Безопасность и ИБ

- Кадры камеры стенд не сохраняет: `camera_check.py` только считает кадры и ищет метки (AGENTS.md, п. 8).
- Запись позы содержит только углы и время, без изображений.
- Мост позы слушает только 127.0.0.1. Для другого ПК в сети нужно явно указать `--host 0.0.0.0` и согласовать это с ИБ.
