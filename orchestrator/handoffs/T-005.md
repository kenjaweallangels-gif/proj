## Итог
Реализован C++ каркас игрока: `ARakisCharacter` (3-е лицо на SpringArm и 1-е лицо на сокете `head` с фоллбеком на высоту глаз; бесшовный переход — TP-камера плавно «влетает» в голову за 0.45 с, затем включается FP-камера и прячется кость головы), `ARakisPlayerController` (Enhanced Input целиком в рантайме через `NewObject`: клавиатура/мышь + геймпад, делегаты Pause/PhotoMode, вибрация и тряска камеры от червя), `ARakisGameMode` (HUD по пути `/Script/Rakis.RakisHUD`, автоспавн червя у `Rakis.Worm.Spawn`). Определение поверхности (Physical Material SurfaceType1..6 + теги `Rakis.Surface.*`), шаги по AnimNotify с таймер-фоллбеком, скорости 220/520/160 см/с, тампер, блокировка ввода для кат-сцен. Добавлены взаимодействие (`IRakisInteractable`, `URakisInteractionComponent`), двери-уплотнители, фальшивый камень, POI и 4 Automation-теста.

## Как проверить
1. Сборка: `Engine/Build/BatchFiles/Build.sh RakisEditor Linux Development -Project=$PWD/Rakis.uproject` (или по `docs/05_install.md`). В этой сессии компилятора не было — сборка не запускалась.
2. Тесты: `UnrealEditor-Cmd Rakis.uproject -ExecCmds="Automation RunTests Rakis.;Quit" -unattended -nullrhi -log` → 4 теста зелёные.
3. PIE на любой карте с полом: виден цилиндр-блокаут игрока; WASD/мышь, Shift — бег, Alt — походка по песку, Space в походке — «сбивка», V — переход FP/TP без скачка, E — взаимодействие, T — тампер на песке (из лога видно удары шума), Esc/P — делегаты (их обрабатывает `ARakisHUD`).
4. Геймпад: левый/правый стик, L3, LB, A, X, RS, Y, Start, View.

## S2: проверка компиляции
Компилятора UE в среде по-прежнему нет — сделана ручная сверка каждого файла зоны (Player, Noise, Hydration, Worm, Interaction, Gameplay, Tests) с API-справкой UE (dev.epicgames.com), плюс механическая проверка скриптом (баланс скобок, `.generated.h` последним include, GENERATED_BODY у каждого UCLASS/USTRUCT/UINTERFACE, свой заголовок первым include в .cpp, каждая объявленная не-inline функция-член определена в .cpp) — замечаний скрипт не дал. Публичные API и сигнатуры контракта §2.2 не менялись.

### Исправления
- `Private/Player/RakisCharacter.cpp`: `UPhysicalMaterial::DetermineSurfaceType(...)` → прямое чтение `PhysMat->SurfaceType.GetValue()` (фоллбек `SurfaceType_Default`). Причина: функция экспортируется модулем **PhysicsCore** (`PHYSICSCORE_API`), его нет в `Rakis.Build.cs` → вероятный LNK2019; доступ к UPROPERTY-полю инлайновый и линковки не требует. https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/PhysicsCore/UPhysicalMaterial
- `Private/Player/RakisCharacter.cpp`: `FMath::Clamp(double, float, float)` в `Input_Look` → `FMath::Clamp<double>(...)`; `Clamp(Size2D()/..., 0.f, 1.f)` → явный `static_cast<float>`. Причина: смешанные double/float аргументы (LWC) — защита от неоднозначности шаблона.
- `Private/Worm/RakisWorm.cpp`: явные `static_cast<float>` для double-компонент (`HeadLocation.Z` в `FInterpConstantTo`, `Delta.Z` в `Atan2`, `Rotation().Yaw` в `FixedTurn`) — та же причина (LWC, смешанные типы в шаблонах FMath).
- `Private/Gameplay/RakisSealDoor.cpp`: `FMath::Max(PanelSize.X, 60.f)` (double, float) → `FMath::Max<double>(PanelSize.X, 60.0)`.
- `Public/Noise/RakisSandWalkComponent.h`: параметр `ComputeRegularity(const TArray<float>& Intervals, ...)` → `InIntervals` (совпадал с членом `Intervals` → C4458/-Wshadow, в UE5 — ошибка; в .cpp уже был `InIntervals`). Сигнатура по типам не изменилась.
- `Public/Player/RakisPlayerController.h`: `uint64 RumbleHandle` → `FDynamicForceFeedbackHandle RumbleHandle` — нативная перегрузка в 5.x принимает/возвращает именно `FDynamicForceFeedbackHandle`. https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/APlayerController/PlayDynamicForceFeedback . Вызовы `PlayDynamicForceFeedback(..., EDynamicForceFeedbackAction::Start/Stop, Handle)` однозначно выбирают нативную перегрузку (латентная требует `FLatentActionInfo`, из целого не конструируется).
- `+ #include "Engine/TimerHandle.h"` (перед `.generated.h`) в заголовки с членами `FTimerHandle`: `RakisCharacter.h`, `RakisNoiseComponent.h`, `RakisHydrationComponent.h`, `RakisInteractionComponent.h`, `RakisWorm.h`, `RakisThumper.h`, `RakisSealDoor.h`, `RakisFalseRock.h`. Причина: IWYU — `FTimerHandle` используется по значению, а `Components/ActorComponent.h` его не гарантирует. https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/FTimerHandle

### Сверено и оставлено без изменений (корректно для 5.6)
- `UCameraShakePattern`: `GetShakePatternInfoImpl(FCameraShakeInfo&) const`, `StartShakePatternImpl(const FCameraShakePatternStartParams&)`, `UpdateShakePatternImpl(const FCameraShakePatternUpdateParams&, FCameraShakePatternUpdateResult&)`, `IsFinishedImpl() const`, `StopShakePatternImpl(const FCameraShakePatternStopParams&)` (`ScrubShakePatternImpl` не обязателен). Поля: `Params.DeltaTime`, `Params.bImmediately`, `OutResult.Location/Rotation`, `FCameraShakeInfo::{Duration,BlendIn,BlendOut}`, `FCameraShakeDuration::Infinite()`. `UCameraShakeBase::bSingleInstance`, `ShakeScale` — публичные, `SetRootShakePattern` есть. https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/FCameraShakePatternUpdateParams , .../FCameraShakePatternUpdateResult , .../FCameraShakeDuration , .../UCameraShakeBase
- `UInputMappingContext::MapKey(const UInputAction*, FKey)` → `FEnhancedActionKeyMapping&` (не deprecated); `FEnhancedActionKeyMapping::Modifiers` — `TArray<TObjectPtr<UInputModifier>>`, публичное. `UInputModifierSwizzleAxis::Order` (`EInputAxisSwizzle::YXZ`), `UInputModifierNegate::bX/bY/bZ`, `UInputModifierDeadZone::{LowerThreshold,UpperThreshold,Type}` (`EDeadZoneType::Radial`), `UInputModifierScalar::Scalar` (FVector), `UInputAction::{ValueType,bTriggerWhenPaused}`. https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/EnhancedInput/UInputMappingContext и соседние страницы плагина.
- `UInstancedStaticMeshComponent::BatchUpdateInstancesTransforms(int32, const TArray<FTransform>&, bool, bool, bool)` — есть; вызов с `TArray` выбирает эту перегрузку (TArrayView-перегрузка требует пользовательского преобразования). `AddInstance`, `ClearInstances`, `GetInstanceCount`, `SetNumCustomDataFloats`, `SetCustomDataValue` — совпадают. https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UInstancedStaticMeshComponent
- `UNiagaraFunctionLibrary::SpawnSystemAtLocation(WorldContext, System, Location, Rotation, Scale, bAutoDestroy, bAutoActivate, ENCPoolMethod, bPreCullCheck)` — порядок аргументов совпадает. `UAudioComponent::SetFloatParameter(FName,float)`, `SetIntParameter(FName,int32)`, `FadeIn/FadeOut`, публичный `Sound`.
- `EAutomationTestFlags::EditorContext | ClientContext | ProductFilter` — компилируется и с namespace-enum (≤5.4), и с enum class + ENUM_CLASS_FLAGS (5.5+).
- override-ы `BeginPlay/EndPlay/Tick/OnConstruction/SetupPlayerInputComponent/SetupInputComponent/InitGame/StartPlay/Initialize/DoesSupportWorldType` — сигнатуры совпадают с базовыми. `CreateDefaultSubobject` — только в конструкторах. Приватных UPROPERTY/UFUNCTION с Blueprint-спецификаторами нет; параметры UFUNCTION не совпадают с именами UPROPERTY класса (UHT shadowing). Затенений членов локальными переменными не найдено (кроме исправленного выше). Имена namespace/статиков в .cpp уникальны в модуле (безопасно для unity-сборки).

### Остающиеся неопределённости
- **Рекомендация оркестратору**: добавить `"PhysicsCore"` в `PublicDependencyModuleNames` `Rakis.Build.cs` (файл вне моей зоны). Сейчас код от неё не зависит по линковке, но любое будущее обращение к функциям `UPhysicalMaterial` её потребует.
- Тип `FDynamicForceFeedbackHandle` в документации не раскрыт (по `HandleAllocator` — целочисленный typedef, ожидаемо `uint64`); инициализация `= 0` и сравнение `!= 0` на этом основаны.
- Сигнатуры `*Impl` у `UCameraShakePattern` — private-виртуалы, на страницах API не публикуются; сверено по известному заголовку `Camera/CameraShakeBase.h` (не менялись с 4.26). Поведение бесконечной тряски с собственным blend-out (`IsFinishedImpl` → `bStopped`) — проверить в PIE (не компиляционный риск).
- Неявные сужения double→float (`float X = Vector.Size2D()` и т.п.) оставлены: ошибкой они становятся только при `UnsafeTypeCastWarningLevel = Error` в Target.cs (по умолчанию выключено).
- Имена типов делегатов (`FOnFocusChanged`, `FOnInteracted`, `FOnNoiseChanged`, ...) уникальны в модуле; совпадение с типами в заголовках движка/плагинов не исключено полностью — проявится только при первой сборке.
- Механический скрипт — эвристика на регулярках (не парсер C++); он не ловит ошибки типов и перегрузок.
