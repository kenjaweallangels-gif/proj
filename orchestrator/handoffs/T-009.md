## Итог
`fx_niagara.py` создаёт все 13 Niagara-систем контракта в `/Game/Rakis/FX/` (копией ближайшего шаблона плагина Niagara, иначе пустой системой + копией эмиттера-шаблона в `FX/Emitters/NE_*`), никогда не перезаписывая уже существующие (ручная доводка сохраняется), пытается добавить User-параметры, создаёт `NPC_RakisWeather` (зеркало MPC) и расставляет постоянные эффекты: позёмку по гребням, пыльные вихри, стену бури на ЮЗ горизонте (L_Rakis_Desert), пыль в луче B5, дымку пряности B3/B2, пылинки у светошаров (L_Rakis_Sietch). `light_setup.py` собирает солнце/атмосферу/туман/облака/ветер/глобальный пост с Lumen и автоэкспозицией, локальные PPV и Local Fog Volume интерьера, светошары (Point Light 2700 K + Light Function мерцания + эмиссивная сфера) и «божественный» луч B5. ## Как проверить
1. `python3 -m py_compile Tools/unreal_python/fx_niagara.py Tools/unreal_python/light_setup.py` — ок.
2. В редакторе после шагов 1–5 сборки: `build_demo.py --only light_setup,fx_niagara`.
3. Лог light_setup: `light_setup Persistent: ... зон интерьера N, PPV N, fog N`, `light_setup Sietch: светошаров N, луч B5: да`.
4. Лог fx_niagara: по каждой NS_* — `existing` / `copy:<шаблон>` / `empty+emitter:<путь>`; предупреждение со списком систем, где User.* нужно добавить вручную; `размещено в пустыне 15, в сиетче …`.
5. Outliner: папки `Lighting/Generated`, `FX/Generated`. В PIE: `Rakis.Weather Storm_Horizon 4` — стена бури и позёмка (после ручной сборки стеков).
6. `stat niagara`, `fx.Niagara.Debug.Hud 1` — частицы в бюджете fx.md §2.
7. Перезапуск скриптов не дублирует акторов.

## Открытые вопросы / риски
- **Главное ограничение**: в UE 5.6 нет публичного Python-API для стека эмиттеров Niagara. Скрипт создаёт ассеты и расставляет их, но модули (Spawn Rate, Curl Noise, Wind Force, Collision, рендереры, материалы) нужно собрать вручную по рецептам fx.md §3 (≈ 15–40 мин на систему, итого ~1 рабочий день). User-параметры, скорее всего, тоже вручную (скрипт пишет список в лог).
- Набор шаблонов в `/Niagara/DefaultAssets/Templates` зависит от версии; если ни один не найден — системы пустые (валидные ассеты, без эффекта), C++ их всё равно спавнит без ошибок.
- Рантайм-ветер: контракт требует `User.WindDirection/WindSpeed`. Скрипт выставляет оверрайды при расстановке, но обновлять их при смене погоды должен код. Предложение для gameplay-programmer (world): WeatherSubsystem раз в 0.5 с пишет User.* в `UNiagaraComponent` акторов с тегом `Rakis.FX.Wind`; альтернатива без кода — эмиттеры читают `NPC_RakisWeather` (fx.md §1). Нужно решение orchestrator.
- Персистентность `set_variable_*` в редакторе (оверрайды на компоненте) зависит от версии — проверить в Details → User Parameters расставленных акторов.
- Маркеры расстановки (`Rakis.FX.SandDrift`, `Rakis.FX.DustDevil`, `Rakis.FX.StormWall`, `Rakis.FX.SpiceHaze`, `Rakis.FX.Motes`, `Rakis.LightShaft`) не входят в таблицу тегов контракта §2.4 — без них используются фоллбек-координаты; level-designer может их ставить. Orchestrator: внести в §2.4?
- `docs/level/layout.md` на момент работы отсутствовал — координаты взяты из ТЗ/контракта (эрг (70000, 20000), скала (150000, 60000), буря (−250000, −300000)); после появления layout.md — проверить/поставить маркеры.
- Луч B5 — Spot Light, а не солнце через шахту (вечернее солнце 8° не попадает в вертикальную шахту) — художественное допущение.
- Тени 30–60 светошаров — главный риск GPU в сиетче (perf_budget.md §3, рычаги §7).
