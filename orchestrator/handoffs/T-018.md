## Итог
Сверил все `unreal.*` символы скриптов level/env/data/char/anim/audio + `rakis_common`/`level_common`/`build_demo` с официальным Python API UE 5.6 (страницы классов `dev.epicgames.com/.../python-api/class/<Class>?application_version=5.6`; все используемые классы есть в индексе 5.6). Исправлены реальные ошибки: `make_level_current` получал `ULevel` вместо `LevelStreaming`, `World.streaming_levels` в Python не существует, `duplicate_and_retarget` вызывался с лишним аргументом, свойство `enable_air_absorption` не существует, карты открывались внутри `ScopedEditorTransaction`, FBX в 5.5+ уходит в Interchange, который игнорирует `FbxImportUI`. Объёмы теперь масштабируются по фактическим bounds кисти. Ландшафт: Python 5.6 не умеет создавать Landscape из файла. Поэтому написан `landscape_import.py`: он проверяет API в рантайме, печатает пошаговую инструкцию, а для уже созданного Landscape сам выставляет трансформ, материал и тег и убирает фолбэк-землю. `env_dunes.py` теперь пишет и `.r16`. В `build_demo.py` добавлены `landscape_import` и необязательные `ai_smart_objects`/`ai_mass_crowd` (пропускаются молча, если файла нет), `main()` каждого шага вызывается ровно один раз.

## Как проверить
```
python3 -m py_compile Tools/unreal_python/*.py Tools/blender/*.py
python3 Tools/blender/env_dunes.py --res 1009          # → Export/heightmap_desert_r16.png + .r16 + .json
python3 Tools/unreal_python/landscape_import.py        # печатает пошаговую инструкцию по JSON
python3 Tools/unreal_python/data_import.py --dry-run
```
Сухой прогон на строгом моке unreal 5.6 (`scratchpad/t018/mock/unreal.py` + `run.py`, это развитие мока T-003): `build_demo.main(--only <все шаги level/env/data/char/audio/landscape>)` два раза подряд, режимы «C++ собран» и «не собран» — FAIL нет, 2055 → 2055 акторов (как у T-003), `load_level` вне транзакций (мок падает, если это не так), CVar Interchange FBX на время импорта = 0, после восстанавливается. Сценарий «Landscape создан вручную с Location = центр»: трансформ исправлен на угол (−131600, −151600, 0)×100, тег, метка и папка выставлены, `Ground_*`/`Dune_*` удалены, повторный `level_blockout_desert` землю не строит. Отсутствующие `ai_*` в сводке «–», не FAIL.
В редакторе: `build_demo.py` → в логе `landscape_import` печатает инструкцию → выполнить §13.1 layout.md → `build_demo.py --only landscape_import,level_blockout_desert`.

## Открытые вопросы / риски
- **Кисть объёмов.** Опираюсь на то, что `spawn_actor_from_class` для подкласса AVolume идёт через `UActorFactoryBoxVolume` (куб 200 см). `fit_box_volume` меряет фактические bounds и предупреждает, если кисти нет. Если в 5.6 это не так, Zone/Nav/Audio-объёмы будут «пустыми»: лог покажет `у объёма нет кисти`, лечится в Details ▸ Brush Settings. В Python кисть не перестроить.
- **NavMesh**: после скрипта может понадобиться Build ▸ Build Paths. Масштаб через Python не вызывает PostEditMove, поэтому навигация может не перестроиться сама.
- **Location в окне New Landscape = центр.** Так помню по исходникам редактора, но в документации явно не сказано. Если это угол, ничего страшного: `landscape_import.py` всё равно ставит точный трансформ сам.
- **CVar `Interchange.FeatureFlags.Import.FBX`.** Если в 5.6 он переименован или не влияет на `AssetImportTask`, FBX уйдёт в Interchange: Nanite включится постобработкой, а вот `destination_name` (`A_` у анимаций) и `skeleton` могут не учесться. Проверить на первом реальном импорте.
- `set_current_level_by_name` сравнивает короткое имя пакета уровня — это не проверено в живом редакторе (есть фолбэк через LevelStreaming).
- `_set_levels` в `level_markup` грузит UWorld подуровней через `load_asset` для `TSoftObjectPtr` — работает, но тяжело; фолбэк через `SoftObjectPath(str)` может не принять строку (он в try).
- Скрипты ни разу не запускались в настоящем UE — только мок и py_compile.
- Чужие шаги (`mat_*`, `fx_*`, `light_*`) на моем моке падают из-за ограничений мока, а не из-за кода. Их в этой задаче не трогал.

## Следующему агенту
- Порядок в любом новом скрипте уровня: `LC.ensure_persistent_with_sublevels()` и `LC.make_current(...)` → `with transaction(...)` → `LC.save_all()` после неё. Не вызывать `load_level`/`new_level` внутри транзакции, менять карту только через `rakis_common.open_map`.
- Объёмы: `spawn(...)`, затем `fit_box_volume(actor, (sx, sy, sz))`, не `set_actor_scale3d(size/200)`.
- FBX-импорт делать только внутри `with legacy_fbx_import():`.
- Теги: `add_tags`/`has_tag`/`actors_with_tag` из `rakis_common`.
- gameplay (AI): `ai_smart_objects.py` и `ai_mass_crowd.py` уже стоят в `build_demo.STEPS` (после `env_dress_sietch` и после `char_crowd_variants`). Нужна функция `main()` без обязательных аргументов и никакой работы при импорте.
- Человеку: один раз выполнить ручной импорт ландшафта (layout.md §13.1). Дальше сборка доводит его сама.
