## Итог
Сделана деформация песка: следы игрока, спутников и горожан, борозды скольжения, кольца тампера, колея и кратер червя. C++ `URakisSandTrailSubsystem` (UTickableWorldSubsystem) рисует в два каскада Render Target (RG16f: R — глубина вмятины в см, G — высота вала в см). Ближний каскад — 2048² на 40.96 м (2 см/тексель), дальний — 1024² на 204.8 м (20 см/тексель). Окна идут за игроком шагом, кратным текселю, и при рецентровке содержимое сдвигается пинг-понг копией без пересэмплинга. Штампы процедурные (без текстур), копятся за кадр и рисуются одним Canvas-проходом на каскад. Раз в 0.25 с следы «заживает ветер»: скорость берётся из MPC `WindSpeed` и `StormIntensity`. `M_Landscape_Sand` (`UseTrails`, включён в `MI_Sand_Erg_Dry` и `MI_Sand_Packed`) по RT темнит и сглаживает песок и гасит рябь. Наклон нормали считается по градиенту из 4 соседних выборок. Ближний каскад вдавливает поверхность через Nanite displacement (вмятины с валом), дальний — через WPO (метровая колея червя). Кроме того, сверены с Python API UE 5.6 все имена в mat_*, fx_*, light_* и mat_graph_lib; найденные ошибки исправлены.

## Как проверить
1. `python3 -m py_compile Tools/unreal_python/mat_*.py Tools/unreal_python/fx_*.py Tools/unreal_python/light_*.py` — ок. Сухой прогон с мок-модулем `unreal` (MagicMock, а также строгий мок без скрытых `MaterialProperty`) проходит без исключений.
2. Собрать модуль Rakis. Новых зависимостей нет: Engine, RenderCore, PhysicsCore уже в Build.cs.
3. Редактор: `build_demo.py --only mat_master_materials`. В логе: `MPC_RakisWeather: 7 скаляров, 6 векторов`, `mat_sand_trails: near, far, stamp, fade, copy`, `Материал M_Landscape_Sand собран`. Если есть предупреждение «выход Displacement … подключите вручную»: открыть M_Landscape_Sand, найти ноду с комментарием «-> Displacement», соединить её с пином Displacement и нажать Apply.
4. Проверить, что ландшафт пустыни использует `MI_Sand_Erg_Dry` / `MI_Sand_Packed`. PIE в L_Rakis_Desert: в логе `SandTrail: каскады готовы`. Пройтись и пробежать — видны следы с пяткой и носком, при беге глубже. Спутники оставляют следы, тампер — кольца, червь (`Rakis.Worm`/ForceSurface) — колею шириной ~30 м и кратер.
5. `Rakis.Weather Storm_Horizon 2` — следы затягиваются за секунды. `Rakis.SandTrails 0` — следы исчезают (MPC w=0). `Rakis.SandTrails.Clear` — следы стёрты.
6. Session Frontend → Automation → `Rakis.Sand` — 3 теста.
7. `stat GPU`: BasePass ландшафта прибавляет ≤ 0.15 мс к варианту с `UseTrails=false`, общий бюджет ≤ 0.3 мс (sand.md §4.5).

## Открытые вопросы / риски
- **MPC**: добавлены `TrailOrigin` и `TrailOriginFar` (разрешение orchestrator). Нужно внести их в контракт §2.5 / §2.8. `build_mpc` удаляет параметры вне списка, поэтому оба добавлены в список скрипта. GUID существующих параметров не меняются.
- **Два каскада вместо одного RT 160 м** — осознанное отступление от ТЗ: при 7.8 см/тексель стопа занимает 3×2 текселя и формы не видно. Цена — 20 МБ VRAM и 10 выборок вместо 5.
- **Displacement из Python**: `MP_DISPLACEMENT` и `MP_CUSTOM_DATA0` в Python 5.6 скрыты (UMETA(Hidden)). Скрипт пробует числовое значение enum (32 и 16, порядок `EMaterialProperty` 5.4–5.6). Если не выйдет — подключить вручную (п. 3); то же для Cloth (CustomData0) в M_Cloth_Worn / M_Spice_Fabric. Без Displacement вмятины ног остаются только в цвете и нормали, колея червя (WPO) работает.
- Компиляция и запуск не проверены: в окружении нет UE. C++-сигнатуры функций рендеринга сверены по Python API 5.6, где отражены их UFUNCTION (`begin_draw_canvas_to_render_target`, `draw_material`, `create_render_target2d`, `clear_render_target2d`, `draw_material_to_render_target`). C++-страницы документации закрыты Cloudflare. Возможные мелочи при сборке: имена `ETextureRenderTargetFormat::RTF_RG16f` и константность `UWorld::GetParameterCollectionInstance` (вызывается через неконстантный `UWorld*`).
- Additive-штампы накапливаются: тропа, по которой прошли несколько раз, глубже. Это ограничено клампом в материале (`TrailMaxDepth*`). Штамп ноги внутри колеи червя добавляет глубину, а не поднимает дно — так задумано.
- Канал R16f: затухание проверено арифметически (≥ 2 ulp за шаг). На очень старых значениях остаются «хвосты» ~1e-4 см — невидимы.
- Нормаль следа считается в касательном ≈ мировом пространстве ландшафта (как RVT-нормаль в T-008). Если ландшафт повёрнут, нужен TransformVector.
- Ландшафт без физматериала считается песком. Слои камня ландшафта должны иметь PhysMaterial SurfaceType2 (Rock), иначе на камне будут следы.
- Шаги, которые игрок отправляет через `OnNoiseReported`, привязываются к ближайшему ACharacter в радиусе 2 м. Если рядом стоят двое, yaw следа может взяться у соседа (косметика).

## Следующему агенту
- Поставить штамп из любого кода или BP: `URakisSandTrailSubsystem::Get(this)->AddStamp(Pos, RadiusCm, Depth01, YawDeg, ERakisStampType::…)`; сбросить: `ClearTrails()` (кат-сцены, телепорт). Для кат-сцены `LS_WormReveal` кратер ставится сам при входе червя в Surface.
- gameplay (core): если появится событие скольжения или падения персонажа, вызывайте `AddStamp(..., Sliding)` напрямую — сейчас скольжение угадывается по уклону пути (>0.45) и скорости.
- level/env: ландшафту пустыни нужен `MI_Sand_Erg_Dry`/`MI_Sand_Packed`; слоям камня — PhysMaterial Rock; в сиетче следов нет (пол не песок).
- Настройки (размер окон, снап, глубины, полураспады, радиус скана) — `[/Script/Rakis.RakisSandTrailSubsystem]` в DefaultGame.ini (файл orchestrator). Если менять разрешение RT, поправить `TrailNearTexels`/`TrailFarTexels` в MI.
- tech-artist: после первого запуска в редакторе проверить в логе `mat_master_materials` предупреждения «выход … подключите вручную» и, если они есть, соединить ноды (Displacement — песок, CustomData0 — ткани).
