## Как проверить
1. `python3 -m py_compile Tools/unreal_python/mat_*.py Tools/unreal_python/light_setup.py` — без ошибок (проверено).
2. Собрать C++ модуль (нужен для `/Project/Rakis` — модуль грузится на PostConfigInit).
3. В редакторе: `build_demo.py --only mat_master_materials,mat_post_process`. В логе: `MPC_RakisWeather: 7 скаляров, 4 вектора`, `Материал M_* собран` без «предупреждений графа», `мастеров 14/14`.
4. Открыть каждый мастер → Apply → нет ошибок компиляции; Stats — сверить инструкции с materials.md.
5. Плоскость 50×50 м с `MI_Sand_Erg_Dry`, `Rakis.TimeOfDay 7`: рябь поперёк ветра, искры против солнца; `Rakis.Weather Storm_Horizon 2` — рябь разворачивается, песок желтеет.
6. `MI_PP_HeatHaze` в глобальном PPV (ставит light_setup): `Rakis.Weather Noon_Approach 1` — марево у земли вдали и у горизонта, на руках/небе нет.
7. Повторный запуск скриптов не плодит ассеты и не меняет GUID параметров MPC.

## Открытые вопросы / риски
- Скрипты не запускались в Unreal (нет редактора в окружении): имена свойств/входов нод взяты по API 5.x, всё рискованное обёрнуто в try/warn. Возможны предупреждения «не удалось соединить» на нодах с нестандартными именами входов (DepthFade, BlackBody, функции WorldAlignedTexture) — правятся одной строкой в `mat_graph_lib.connect` (таблица синонимов).
- Custom-ноды получают WorldPosition в LWC → движок демотирует во float (точность ~мм в пределах ±5 км — нормально для среза).
- Следы/колея червя: материал готов (`UseTrails`, `T_TrailMask`, `MPC.PlayerPosition`), но рисование в Render Target — код gameplay-programmer (core). Вопрос orchestrator: поставить подзадачу «URakisSandTrailComponent: RT 2048² вокруг игрока, штамп шага, полоса червя» (рецепт в sand.md §4). `MPC.PlayerPosition` уже пишет `URakisWeatherSubsystem` (проверено), `SandTint.A` = DustDensity — материалы канал A не используют.
- RVT-ассеты и Virtual Texture Volume — ручная работа или level/env-скрипт (sand.md §5).
- Добавлены служебные ассеты вне списка контракта: `M_Blockout`, `M_LF_GlowglobeFlicker`, `M_FX_Dust`, `MI_LF_GlowglobeFlicker_A/B/C`, `MI_FX_Dust_*`, `MI_FX_Motes` — orchestrator, при согласии внесите в §2.5.
- `MI_Blockout_*` унаследованы от простого `M_Blockout` (без Custom/include), чтобы блокаут работал даже без собранного модуля.
- `CloudCoverage` → параметр `Coverage` у материала облаков: у движкового материала его нет, нужен `MI_VolumetricCloud_Rakis` (вручную, lighting_weather.md §4).
