# Комплектация — состав изделий, заказы, дефицит

Система для планово-диспетчерского отдела и смежных служб машиностроительного предприятия.
Главная идея — три понятных экрана вместо десятка модулей:

| Раздел | Для чего | Что там делают |
|---|---|---|
| **Заказы** | Что сейчас комплектуем | Заказ = изделие × количество × срок. Открыл — дерево состава с галочками «пришло», частичный приход («пришло 3 из 8»), фильтр «только чего не хватает», ведомость в Excel, печать |
| **Спецификации** | Из чего состоят изделия | Перетащил Excel — состав загрузился (вложенность по колонке «Входит в», «Уровень» или просто отступами). Правка прямо в дереве: название, обозначение, количество, добавить/убрать строку. История редакций ведётся сама |
| **Дефицит** | Чего не хватает по всем заказам | С учётом склада и уже заказанного; дата «заказать до» по циклу поставки; ведомость в Excel; кнопка «Передать снабжению» создаёт заказы поставщикам |
| **Сборка** (из заказа) | Пошаговая сборка в цехе и 3D-плеер | Последовательность строится сама (детали → узел → изделие). **Реальная**: большая карточка «текущий шаг / следующий», кнопки Сделано / Назад / Пропустить, факт (кто, когда) пишется в заказ. **Виртуальная**: 3D-модель изделия, детали прилетают на место по шагам, скорость 0,25–4×, направление сборка/разборка, перемотка. Горячие клавиши, полноэкранный режим, **закреплённое окно поверх CAD и Excel** |
| **Ещё** | Для специалистов | Склад и бухгалтерия, закупки/кооперация/ОТК, план и расчёт потребности, извещения об изменении с согласованием, аналитика и прогнозы, интеграция с 1С, пользователи и роли, ИИ-ассистент |

Скриншоты — в `docs/screenshots/`, архитектура и модель данных — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

### Сборка: горячие клавиши и окно поверх других программ

| Клавиша | Действие |
|---|---|
| `Пробел` / `Enter` / `Num 0` | реальная — шаг сделано; виртуальная — пуск/пауза |
| `Backspace` / `Num .` | отменить последний шаг |
| `S` | пропустить шаг |
| `←` `→`, `Home` `End` | листать шаги / в начало / в конец |
| `+` `−` | скорость анимации |
| `R` | направление: сборка ⇄ разборка |
| `V` | переключить реальная / виртуальная |
| `F` | на весь экран · `?` — подсказка |

«📌 Закрепить окно поверх» открывает панель сборки отдельным окном, которое остаётся над CAD, Excel и другими
программами (Chrome / Edge 116+; в других браузерах — отдельное обычное окно). Клавиши действуют, пока это окно
активно. Чтобы нажимать их, не покидая CAD, используйте педаль или отдельный нумпад с AutoHotkey-скриптом
`docs/assembly-hotkeys.ahk` (F13–F18 пересылаются в окно сборки).

**3D-модель** загружается в спецификации изделия: STEP/STP (конвертируется на сервере), GLB/glTF, STL, OBJ.
Для анимации по шагам имена деталей в модели должны содержать обозначения из спецификации — кнопка
«Имена деталей в модели» покажет, что увидел сервер.

## Развёртывание (Docker)

Нужен сервер или компьютер с Docker (Compose v2). Скачайте архив проекта, распакуйте и выполните:

```bash
cd deploy
./up.sh                 # создаст .env со случайными паролями, сертификат, соберёт и запустит всё
```

Откройте **https://<адрес сервера>** (для самоподписанного сертификата браузер спросит подтверждение).
Вход: `admin / admin12345`. Демо-данные (изделие «Редуктор РЧ-100», склад, план) включены — отключаются
`PLM_SEED_DEMO=false` в `deploy/.env`.

Что поднимается: PostgreSQL 16 → приложение (API + интерфейс) → nginx (TLS, защита входа от перебора) + ежедневные
бэкапы в `deploy/backups`. Локальная ИИ-модель **по умолчанию не разворачивается** — ассистент работает в режиме
команд («состав …», «дефицит», «куда входит …»).

**Уже есть свои модели на ПК** (Ollama, LM Studio, Jan, vLLM и т.п.)? В `deploy/.env` укажите
`PLM_LOCAL_LLM_ENABLED=true`, `PLM_LOCAL_LLM_URL=http://host.docker.internal:ПОРТ/v1`, `PLM_LOCAL_LLM_MODEL=<название>`
и выполните `docker compose up -d app`. Кнопка «Проверить подключение» в «Ещё → Пользователи, роли → ИИ-ассистент»
покажет список моделей с сервера. Ничего нет — `WITH_LLM=1 ./up.sh` поднимет Ollama в контейнере.

Полезное: `docker compose logs -f app` — логи; `docker compose down` — остановить (данные сохраняются);
`./make-certs.sh plm.corp.local` — сертификат на своё имя; порты меняются в `docker-compose.yml` у `nginx`.

## Роли

Из коробки 13 ролей (плановик ПДО, конструктор, главный конструктор, технолог, мастер, ОТК, ОМТС, ОПК, кладовщик,
бухгалтер, руководство, инженер производства, администратор). Каждая видит только свои разделы. Права — 26 штук
вида «раздел:действие», настраиваются в «Ещё → Пользователи, роли». Уровень допуска (0–3) скрывает конфиденциальные
изделия от тех, кому они не положены, и не даёт отправлять их в облачный ИИ.

Демо-учётки: пароль = `логин12345` для `admin`, `pdo`, `ivanov` (гл. конструктор), `petrova`, `sidorov`, `master`,
`otk`, `omts`, `opk`, `director`.

## Разработка

```bash
cd backend && pip install -r requirements.txt && uvicorn app.main:app --reload --port 8000   # API + /api/docs
cd frontend && npm install && npm run dev                                                    # UI на :5173
cd backend && python -m pytest -q                                                            # 18 тестов
```

Схема БД — миграции Alembic (`backend/alembic/`), применяются при старте автоматически;
после правки моделей: `alembic revision --autogenerate -m "..."`, `alembic upgrade head`, `alembic check`.
Собранный фронтенд раздаёт сам бэкенд, поэтому в проде это один контейнер приложения.
