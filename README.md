# ПрофПЛМ — управление составом изделий, изменениями КД, планированием и снабжением

Корпоративная веб-система (PLM + MRP-lite) для машиностроительного предприятия: ревизии составов,
извещения об изменении, комплекты, дефицит, MRP от товарного плана, закупки/кооперация, входной
контроль, склад с автоматическими проводками, себестоимость и трудоёмкость, аналитика и
ИИ-ассистент (локальная LLM для конфиденциальных данных + облачная по разрешению).

Подробная архитектура, модель данных и ролевая модель — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Быстрый старт (разработка)

```bash
# backend (SQLite по умолчанию, демо-данные создаются автоматически)
cd backend && pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000        # API: http://localhost:8000/api/docs

# frontend
cd frontend && npm install && npm run dev        # UI: http://localhost:5173 (прокси /api → 8000)

# тесты
cd backend && python -m pytest -q
```

### Миграции БД (Alembic)

Схема управляется миграциями в `backend/alembic/`; при старте приложение само выполняет `upgrade head`.
После изменения моделей:

```bash
cd backend
alembic revision --autogenerate -m "что изменилось"   # создать миграцию (проверьте diff!)
alembic upgrade head                                   # применить
alembic check                                          # убедиться, что модели и БД совпадают
```

Собранный фронтенд (`npm run build`) раздаётся самим бэкендом с `/`, так что для корп. сети
достаточно одного процесса за nginx.

Демо-учётки (пароль = `логин12345`): `admin`, `ivanov` (гл. конструктор), `petrova` (конструктор),
`sidorov` (технолог), `pdo`, `master`, `otk`, `omts`, `opk`, `director`.

## Развёртывание в корпоративной сети

```bash
cd deploy && ./up.sh                # первый запуск одной командой: .env, сертификат, сборка, старт, загрузка LLM
```

Вручную: `cp .env.example .env` (задать пароли и `PLM_SECRET_KEY`), положить `certs/plm.crt` и `certs/plm.key`
от корпоративного CA (или `./make-certs.sh` для самоподписанного), `docker compose up -d --build`,
`docker compose exec ollama ollama pull qwen2.5:14b-instruct`.

Состав: PostgreSQL 16 → приложение (4 воркера uvicorn) → nginx (TLS, rate-limit на вход) + Ollama
(локальная LLM, данные не покидают сеть) + ежедневный `pg_dump` в `deploy/backups`.

## Что умеет

| Область | Возможности |
|---|---|
| Номенклатура | 9 типов: изделие, сборочная единица, деталь, ПКИ, кооперация (изготовление), операция на стороне (покрытие, термообработка…), крепёж/стандартные, материал, оснастка; гибкие атрибуты; уровень конфиденциальности 0–3 |
| Состав | ревизии (черновик → выпущена → устарела), дерево с развёрнутыми количествами, применяемость, защита от циклов, статус готовности по остаткам (как в прототипе: зелёный/жёлтый/красный) |
| Изменения КД | извещения по ГОСТ 2.503 (код причины, срочность, задел), маршрут согласования по ролям, проведение = автоматический выпуск новых ревизий |
| Техпроцесс | операции по рабочим центрам (Тпз/Тшт), операции на стороне со стоимостью, оснастка |
| Себестоимость | рекурсивная калькуляция: материалы / ПКИ / кооперация / труд, трудоёмкость в н-ч |
| Планирование | товарный план → запуск = комплект с замороженной ревизией + наряд; MRP с датами запуска (назад от срока по циклам), партии, min-запас; дефицит по комплектам |
| Комплекты | чек-лист комплектации с выдачей со склада, материализованные пути для больших составов |
| Снабжение | заказы ОМТС и ОПК (кооперация), автоформирование из MRP по поставщикам, приёмка → карантин → решение ОТК → оприходование |
| Склад | журнал движений (append-only) + материализованные остатки, средняя цена, резервы; проводки 10/10.2/20/43/60/94, ОСВ, экспорт в 1С |
| Аналитика | KPI-дашборд, прогноз расхода (Хольт) + точка заказа + страховой запас, скоринг рисков снабжения, надёжность поставщиков, загрузка участков |
| Импорт | адаптивный Excel: поиск шапки, сопоставление колонок по синонимам, родитель/уровень, авто-типизация; состав, план, остатки |
| Интеграции | 1С:ERP/УПП/КА через OData, произвольные БД через SQL, REST; секреты только из переменных окружения |
| ИИ | правила (всегда) → локальная LLM (Ollama/vLLM, OpenAI-совместимый API) → облако (Claude) по явному разрешению; инструменты чтения выполняются сразу, изменяющие — только после подтверждения; всё в аудите |
| Безопасность | JWT access/refresh с версией токена, bcrypt, блокировка после 5 неудач, RBAC (26 прав, 13 ролей из коробки), допуск к данным (ABAC), журнал аудита, security-заголовки |
