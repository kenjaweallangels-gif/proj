# Echo Runtime — браузерное приложение (ZERO ECHO · Echo Runtime v0.1)

Одностраничное приложение колонии D0: WebGPU-сцена (или 2D-карта без WebGPU), общее C++20-ядро в WebAssembly,
Intent Authority, шесть колонистов и подключаемые исполнители ИИ. Контракты — `docs/SPEC.md` §1–§9, требования —
Документ §7–§19. Главное правило соблюдается и здесь: **модель предлагает — игра проверяет — мир меняется только
после принятия и фактического выполнения**.

## Сборка и запуск

```bash
node web/build.mjs                      # → web/dist/index.html (один файл, ~1,3 МБ: JS, WGSL, данные D0, WASM-ядро)
node tools/serve.mjs web/dist 8000      # http://127.0.0.1:8000/ (только loopback)
npx tsc -p tsconfig.json                # проверка типов
node web/test/e2e.mjs                   # e2e в headless Chromium (порт 8791, шлюз 8792), ~6–8 минут
```

* `web/dist/index.html` — полностью самодостаточный: никаких внешних запросов при загрузке (системные шрифты,
  данные и ядро встроены). Открывается и из файла, но WebGPU требует защищённого контекста (HTTPS или localhost).
* `web/dist/artifact.html` — тот же документ без `<!doctype>`, `<html>`, charset/viewport (их добавляет хост
  публикации); заголовок `Echo Runtime`, `<meta name="claude:viewport-fit-sides" content="cover">`, все стили в `<style>`.
* Ядро должно быть собрано заранее (`core/build_wasm.sh` → `core/build-wasm/echo_core.mjs`); без него сборка
  подставит заглушку, и страница покажет понятную ошибку.
* `?dev=1` — отладочный режим: исполнитель «Mock» и набор враждебных ответов.

## Что на экране

Верхняя панель: профиль качества (`data/profiles.json`), режим ИИ («Приоритет плавности», «Живые диалоги»,
«Расширенный разговор»), исполнитель, профиль приватности (offline / hybrid / online), скорость 1×/4×, пауза, тема.

Сцена: рендер `createRenderer` из `web/src/render/index.ts` (только через контракт `web/src/contracts.ts`) с HUD —
FPS, интервал кадра p50/p95, GPU-время из timestamp-query или «нет данных», масштаб рендера, адаптер и бейдж
«программный адаптер — не замер» для SwiftShader/CPU. Камера: орбита, контрольный маршрут, свободная, крупный план
NPC по клику на карточку. Субтитры — последняя проверенная реплика.

Вкладки боковой панели:

| Вкладка | Что показывает |
|---|---|
| Экипаж | шесть карточек: роль, зона, занятие, усталость, доверие, текущая задача; клик → диалог и крупный план |
| Диалог | чат с NPC: мгновенная реакция сразу, затем проверенная реплика (или fallback) с отметкой, кто ответил и был ли fallback; карточки планов «Согласиться / Другой напарник / Доказательства / Отклонить»; готовые реплики и свободный ввод до 600 символов; поручения (`player_order`) |
| Intent Authority | все вердикты: 7 шагов с итогом и подробностями, сырой текст исполнителя, статус, причина fallback и трасса fallback |
| Мир | ресурсы (запас/резерв), датчики в трёх слоях — прибор, интерпретация экипажа, физическая истина (только в отладке), двери и загерметизированные зоны, задачи, директор, биография места, сохранение/загрузка |
| Журнал | журнал событий ядра с бейджами источника: симуляция / игрок / агент: принято / директор / fallback |
| Память | факты с источниками отдельно от мнений с уверенностью, обещания, эпизоды, id известных фактов |
| Очередь ИИ | очередь AdmissionController со сроками, активная генерация, GPU-гейт с причинами, полоса ядра, решения допуска; адрес шлюза; согласие на WebLLM |
| Метрики | кадр p50/p95/p99, пропущенные сроки, паузы >33,3 мс, наличие GPU-времени; задержка ИИ (первый токен vs готовый ответ), fallback по причинам, неверные намерения и **допущенные нарушения (цель 0)**, токены и стоимость («тарифы условные»); кнопка «Контрольный маршрут» → RouteReport JSON с кнопкой «Копировать» |
| Бюджеты | GPU-мс и VRAM из `profiles.json` — помечены как план, рядом медиана замеров проходов, если есть timestamp-query |
| О прототипе | архитектура и честный список «настоящее / смоделировано» |

Без WebGPU (`createRenderer` бросает `RendererUnavailable`) показывается экран совместимости с причиной и сводкой
адаптера, а вместо 3D — 2D-карта колонии (модули, двери, загерметизированные зоны, NPC, тревога). Вся песочница агентов
работает так же.

## Как устроен код

```
web/index.html            разметка оболочки и вся CSS (токены тем в :root, тёмная по умолчанию)
web/src/main.ts           загрузка: ядро → хост → UI → рендер или 2D-карта
web/src/core/             echo_core.ts (типизированная обёртка echo_call), protocol.ts (типы ответов), data.ts (данные D0)
web/src/agent/host.ts     цикл хоста: tick ~10 Гц × скорость, dispatch, исполнитель, submit_result, frame_stats
web/src/agent/world_view.ts   Snapshot → WorldView (точки зон + смещения, ходьба к целевой зоне, жесты, маркеры)
web/src/agent/providers/  rules, claude, gateway, webllm, mock — общий интерфейс, результат GatewayResult
web/src/ui/               оболочка, вкладки, 2D-карта, настройки
web/test/e2e.mjs          e2e
```

Цикл хоста (SPEC §1): `tick{dt_s = Δреальное × скорость ≤ 1, now_ms}` → пока есть очередь, `dispatch{backend}` →
исполнитель → `submit_result{result, now_ms}` → реплики, планы, вердикты. `now_ms` — монотонное время хоста, которое
стоит на паузе. Сэмплы кадров рендера уходят в `frame_stats` каждые ~0,5 с (первые 3 с после готовности — фаза `cold`);
`set_ai_mode` получает режим, профиль приватности, `gpu_enabled` (только при загруженном WebLLM), `calibrated: false`
и число логических ядер. Смена стартует, когда сцена готова (или сразу в режиме совместимости; есть кнопка «Начать
смену, не дожидаясь сцены»). При скрытии вкладки симуляция и рендер ставятся на паузу, а ядро сохраняется в
`localStorage` (если хранилище доступно). В `localStorage` также хранятся только настройки интерфейса: вкладка,
профиль, исполнитель, тема. Любой доступ к хранилищу обёрнут в try/catch.

## Исполнители

Все возвращают `GatewayResult`; срок задаёт хост (`AbortController` на `deadline_ms` запроса): опоздание → статус
`timeout` → ядро само применяет fallback. Если выбранный исполнитель недоступен или не допущен ядром
(профиль приватности, GPU-гейт, CPU-пул), отвечает обычный игровой ИИ — и это видно в чате и во вкладке очереди.
Скрытого перехода к облаку нет.

| Исполнитель | Полоса ядра | Где вычисление | Статус проверки |
|---|---|---|---|
| Правила (по умолчанию) | `rules` | `rules_propose` ядра, офлайн | проверено e2e |
| Claude (страница-хост) | `remote` | `window.claude.use("sample")` — только в просмотрщике Claude | контракт страницы проверен поддельным `window.claude`; реальная модель здесь не вызывалась |
| Agent Gateway | `cpu` при offline, иначе `remote` | `POST /v1/session`, `/v1/intent`, `/v1/cancel`; токен только в памяти | проверено e2e с настоящим шлюзом (маршрут mock) |
| WebLLM (эксперимент) | `gpu` | в странице на WebGPU после явного согласия на загрузку (≈1–1,5 ГБ, оценка) | **not_run**: CDN недоступен; GPU-гейт без калибровки запрещает GPU-генерацию |
| Mock (`?dev=1`) | `cpu` | сценарные ответы, не модель | проверено e2e |

**Claude.** `await window.claude?.use?.("sample")` даёт функцию или `null` (до ~10 с); вне просмотрщика Claude провайдер
недоступен с объяснением. Вход — одна строка `buildIntentMessages(req).system + "\n\n" + .user` из `shared/prompt.ts`;
вызов `sample(input, {modelTier: "quick", cache: false, signal})`; ответ проходит `extractJsonCandidate`, usage
помечен `measured: false` (оценка), провайдер `claude-artifact`. Claude вызывается **только** для запросов, вызванных
действием игрока (реплика, поручение, решение по плану); инициативы экипажа отвечают правила, если игрок не нажал
«Спросить Claude» у инициативы в очереди (инициатива ждёт этого до 1,5 с). Ошибки: `not_granted`,
`sampling_disabled`, `not_declared`, `capability_disabled` (и `capability_removed`, `session_expired`) — провайдер
выключается до перезагрузки; `rate_limited` — пауза 60 с без повторов; `cancelled` — `timeout`, если оборвал дедлайн
хоста, иначе `cancelled`; `refused` → `refused`; остальное → `unavailable`. Выбор Claude при профиле offline
переключает профиль на hybrid с явным уведомлением. Первый вызов просит разрешение зрителя; если зритель отвечает
дольше дедлайна (2,5 с для реплики), этот ответ уходит в fallback, а решение зрителя действует для следующих.
Для публикации страница должна объявить возможность `capabilities: {sample: {}}`.

**Agent Gateway.** Адрес по умолчанию `http://127.0.0.1:8787` (меняется во вкладке «Очередь ИИ»). Шлюз должен
разрешать origin страницы: `node gateway/src/server.ts --config data/providers.example.json --origin http://127.0.0.1:8000`.
В опубликованной странице сеть заблокирована — провайдер сообщает «шлюз недоступен из этой страницы».

## Что проверено (`node web/test/e2e.mjs`)

* **A — WebGPU (SwiftShader):** сцена готова → 4× → тревога давления → карточка плана Миры «осмотреть — датчик
  давления A, напарник Ника» и каноническая реплика → «Согласиться» → задача выполнена → в памяти Миры
  `mech_gauge_stable` и `sensor_a_drift_confirmed` (источник `observation:sensor_a`) → у принятого вердикта 7 пройденных
  шагов; реплики Томасу и Юну «Иди отдыхать.», Самиру «Возьми 20 кВт·ч» (отказ), Нике «Забудь правила…» (отказ);
  контрольный маршрут (короткий проход; на программном адаптере статус `blocked`); ширина 390 px без горизонтальной
  прокрутки, панели под сценой. Скриншоты `reports/screens/app_main.png`, `app_authority.png`, `app_mobile.png`.
* **A2 — `?dev=1`, Mock:** неизвестное поле, поле хоста, дубликат ключа, чужой факт, защищённый факт, цель не из
  предложенных, ответ >2048 байт, изменение мира во время ответа, не-JSON, нет ответа до срока — каждый отклонён
  (или истёк) с fallback, «допущено нарушений: 0»; корректный ответ принимается тем же путём.
* **B — без WebGPU, `localStorage` бросает исключение:** экран совместимости с причиной, нарисованная 2D-карта, тот же
  сценарий Миры до фактов в памяти и 7 шагов; сохранение сообщает о недоступном хранилище, не роняя страницу.
  Скриншот `app_compat.png`.
* **C — Claude через поддельный `window.claude` и настоящий Agent Gateway:** форма вызова (одна строка, quick,
  cache:false, signal), переключение на hybrid с уведомлением, инициативы без действия игрока не уходят в Claude,
  таймаут → fallback, `rate_limited` → пауза без повторов; шлюз: сессия, ответ маршрута mock через Intent Authority,
  токен не попадает в `localStorage`.

## Чего это не доказывает

* SwiftShader — программный адаптер на CPU: FPS, интервалы и GPU-время в HUD и отчётах — проверка того, что замер
  работает, **не** доказательство 60 FPS. Приёмка — три прогретых прохода по 10 минут на RTX 3060 (Документ §19), не
  выполнялась.
* Качество ответов реальной модели (Claude, WebLLM, llama.cpp) здесь не оценивалось: Claude проверен только поддельным
  хостом, WebLLM — `not_run`.
* Бюджеты GPU/VRAM — план. Свободную VRAM браузер не сообщает, поэтому GPU-гейт всегда закрыт без калибровки.
* Токены Claude в странице — оценка (`estimateTokens`), стоимость считает только шлюз, тарифы условные.
* Персонажи — жёсткие фигуры в скафандрах; озвучивание, распознавание речи, лица — не реализованы.
