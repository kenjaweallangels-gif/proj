# Рендер D0: долина Марса и колония (WebGPU + WGSL)

«Красивый мир. Устойчивый кадр.» — браузерный рендер сцены D0 по Документу (§1, §2, §4, §5, §7, §19).
Нативный Dawn в этой среде недоступен, поэтому рендер написан на TypeScript + WGSL и работает в браузере;
WGSL — общий язык шейдеров из Документа, проходы и бюджеты те же, что планируются для нативной версии.

**Честность.** Всё, что ниже сказано о скорости, — проектные бюджеты, а не замеры. В этой среде WebGPU работает на
SwiftShader (CPU): кадры занимают секунды, такие цифры не являются доказательством 60 FPS и в отчёте маршрута
помечаются `blocked` с пометкой «SwiftShader/CPU — не доказательство производительности». Решающий прогон —
контрольный маршрут на RTX 3060 (Документ §19).

## Контракт

`createRenderer(opts)` из `index.ts` строго по `web/src/contracts.ts`:

* нет `navigator.gpu`, адаптера или устройства, небезопасный контекст → бросается объект `RendererUnavailable`
  (`no-webgpu | no-adapter | device-failed | insecure-context`), страница не падает;
* `onStatus`: `probing → compiling (progress) → baking (progress) → ready`, при потере устройства
  `lost → recovering → compiling → baking → ready`, при скрытой вкладке/`pause()` — `paused`;
* `onFrame(FrameSample)` на каждый кадр: интервал rAF, CPU-время сборки и submit, GPU-время из `timestamp-query`
  (кольцо из 6 буферов чтения, без блокировки CPU; если слот занят или функции нет — `gpuMs: null`, CPU-время
  никогда не подставляется), `passes` по группам бюджета, `renderScale`, `internalSize`.
  Сэмпл с GPU-временем приходит на несколько кадров позже — когда готов результат таймера.
* `setProfile`, `setWorldView`, `setCameraMode('orbit'|'free'|'route')`, `focusActor(id|null)`, `setRouteTime(t)`,
  `runRoute(opts)`, `pause/resume`, `destroy`.

Дополнительно (не контракт, для `render-dev.html` и автоматизации): `debugInfo()`, `debugProbe()` (чтение HDR-кадра:
NaN/Inf, чёрные пиксели, экспозиция, SH-освещённость), `simulateDeviceLoss()`, `setTonemapper('aces'|'agx')`,
`setExposureCompensation(ev)`, `setRoutePlaying(bool)`.

## Проходы кадра и бюджет N60

Группы — из `data/profiles.json → gpu_budget_n60_ms`. Плановые значения — цель для RTX 3060, **не замер**.

| Группа | План, мс | Что в ней |
|---|---|---|
| `culling_depth_service` | 1,0 | GPU-отсечение и выбор LOD камней (compute, indirect draw); depth prepass, если включён профилем (N60) |
| `shadows` | 2,0 | Каскадная карта теней (1–3 каскада по профилю, `depth32float`) для колонии, ровера, экипажа и камней рядом с камерой; тени рельефа на рельеф — запечённые |
| `opaque` | 4,3 | Forward PBR: CDLOD-рельеф, колония одним статическим батчем, ровер, маяки, детали биографии, инстансы камней |
| `character` | 1,2 | Фигуры экипажа (отдельный проход — чтобы видеть его цену) |
| `atmosphere_transparency` | 1,0 | Небо Марса и солнце, пыль у камеры (число частиц из профиля), ограниченная прозрачность: свечения ламп, маяки, пульс тревоги у датчиков, барьеры загерметизированных зон, отметки биографии |
| `ao_reflections_post_ui` | 2,0 | AO в половинном разрешении, автоэкспозиция (compute, без чтения на CPU), bloom (цепочка mip ½…1⁄32), ACES-тонмаппинг (AgX — альтернатива), FXAA во внутреннем разрешении, пространственный апскейл Lanczos-2 с анти-ringing до canvas |
| `upload_reserve` | 0,5 | Запись uniform/instance-буферов (`writeBuffer`); отдельного прохода нет |

План рендера 12,0 мс, запас до 16,67 мс — драйвер, вариации, present; это **не** слот для LLM (Документ §5, §11).

## Сцена

**Запекание (один раз при загрузке, честный прогресс).** Compute-шейдеры `bake_*.wgsl`, разрешение
`profile.render.bake_resolution` (W60: 1024², W-low: 512², N60: 2048²), три вложенных уровня вокруг колонии
(12 км, 3 км, 750 м; у W60 тексель 11,7 / 2,9 / 0,73 м). Каждый уровень — та же функция рельефа с отрезанными
октавами выше частоты Найквиста, поэтому переходы между уровнями бесшовные.
* Рельеф по `d0_layout.json → terrain`: долина вдоль `valley_axis_deg` со слоистыми террасированными стенами,
  отрогами и боковыми каньонами (domain-warped fBm + ridged noise + «эрозионный» fBm), плато со столовыми горами,
  останцы на дне, хребты за долиной, кратер (вал, оползневые террасы, центральная горка, выбросы), выровненная
  площадка колонии с плавным спадом, лавовый уступ с обрывом, в котором выход лавовой трубки (`cave_mouth`).
* Нормали, кавитация, маски материалов: пыль, реголит, базальт, светлые осадочные слои, скальные склоны, дорожки и
  колея ровера.
* Свет: видимость солнца (марш к солнцу по всем уровням с мягкой полутенью), небесный AO (горизонт в 8
  направлениях), затемнение пещеры. Небо: таблица рассеяния (CO₂ + пыль: однократное + приближённое многократное
  рассеяние, сильный вперёд-рассеивающий пик пыли — голубоватое свечение у низкого солнца), сферические гармоники L2
  неба с отражением от грунта, цвет солнца у поверхности.
* Камни: рассыпка по seed на GPU по маскам геологии (больше у базальтовых обрывов, осыпь под пещерой, меньше в пыли),
  без камней на площадке колонии, дорожках и в трубке. Число — `rock_instances` профиля.

**Рельеф во время игры — CDLOD** (Strugar): квадродерево по всей карте, диапазоны LOD по расстоянию, вершины
плавно морфятся к следующему, более грубому уровню — без трещин и «щелчков». Сетка патча из `terrain_grid`
профиля, дальность — `terrain_view_distance_m`; дальний край растворяется в дымке, а не обрезается.
Вблизи камеры добавляются процедурные детали: трипланарный рельеф нормалей, зерно, отдельные освещённые камешки
и галька с контактной тенью.

**Атмосфера.** Небо из таблицы рассеяния с солнечным диском, слабые перистые облака из водяного льда; воздушная
перспектива: равномерная пыль + приземная дымка с экспоненциальной высотой, которая подчёркивает масштаб, но не
закрывает сцену. Солнце — `d0_layout.json → sun` (азимут 250°, высота 17°).

**Колония** из `layout.modules/props`: купол с рёбрами и окнами, шлюз с открытой дверью и интерьером, цилиндрические
модули (кольца, панели, окна с эмиссией, оборудование на торцах, маяки), коробчатые модули, ангар, гермопереходы,
солнечное поле, антенна, баки, мачты освещения, ровер (кузов + 6 колёс по рельефу), арка и трубка пещеры с
освещением экспедиции. PBR-материалы: металл, окрашенные панели с выветриванием, пыль на верхних гранях.

**Экипаж** из `WorldView.actors`: стилизованные фигуры в скафандрах (шлем с золотым визором, ранец, цветовые
акценты из `ActorView.color`), процедурные ходьба/ожидание, жесты `nod, point_at_target, look_at_player, pause, wary,
shrug, check_device`, поворот головы к `lookAt`, ходьба к `target`, выталкивание из модулей. Модель не порождает
движений скелета — только выбирает проверенные метки (Документ §14).

**Состояния мира**: аварийный свет (вращающиеся красные маяки + мерцающие красные источники + усиление пыли),
пульс тревоги у датчиков (`markers`), загерметизированные зоны (красные окна, маяки, полосатый барьер), детали
биографии места у якорей (наружная стойка у модуля + блик).

**Свет**: солнце (каскады × запечённая видимость рельефа), SH-освещение неба × запечённый AO, отражения из таблицы
неба, до 24 локальных источников (выбор по вкладу; фонарь камеры на участке пещеры).

**Разрешение**: canvas = CSS-размер × min(DPR, `max_dpr`), не больше площади `profile.output`; внутреннее
разрешение = × `render_scale` (W60: 0,833 → 1600×900 при 1920×1080), затем апскейл. UI — HTML поверх canvas в
родном разрешении. Динамическое разрешение — только если профиль его включает (`N60_balance`), управление по
измеренному GPU-времени; без GPU-таймера масштаб не меняется. Масштаб всегда в `FrameSample.renderScale`.

## Камеры и контрольный маршрут

* Орбита (мышь/колесо/касания), свободная (WASD + мышь), маршрут: позиция — Catmull-Rom по
  `control_route.keys`, направление взгляда — сглаженный slerp между ракурсами ключей (интерполяция точек взгляда
  разворачивала бы камеру к самой далёкой точке почти сразу). События: `lights_dim`, `torch_on/off`, `focus_mira`
  (взгляд на голову Миры), `emergency_on/off`, `rover_follow` (ровер едет по колее к пещере).
* `setRouteTime(t)` — детерминированный кадр маршрута (эталонные ракурсы), `focusActor(id)` — плавный крупный план.
* `bench/route.ts → runRoute`: прогревочные и измеряемые проходы, маршрут масштабируется во времени до
  `passDurationS`; p50/p95/p99/max/mean интервалов, CPU и GPU (или `unavailable`), доля пропущенных сроков
  (> 1000 / `target_fps`), паузы > 33,3 мс, максимальная пауза, холодный старт, статистика по сегментам, заметки.
  Вердикт `pass/fail` только на аппаратном адаптере; на программном — `blocked`.

## Надёжность

Все конвейеры создаются `createRenderPipelineAsync`/`createComputePipelineAsync` заранее с прогрессом
(`compiling`); ошибки WGSL выводятся с номером строки. Не больше двух кадров в полёте (нет неограниченной очереди
GPU). `device.lost` → `lost` → новое устройство, конвейеры, запекание → `ready` (до 5 попыток). Изменение
размера — каждый кадр; скрытая вкладка — пауза. Ошибки валидации WebGPU собираются в `debugInfo().validationErrors`.

## Проверка в этой среде

`node web/build.mjs`, затем `node tools/serve.mjs web/dist 8781` и `render-dev.html?profile=W60&shot=mars_horizon`
(параметры: `shot=mars_horizon|surface_to_cave|mira_at_equipment|wide_colony|emergency`, `cam`, `ui=0`, `ao`,
`bloom`, `scale`, `tm=aces|agx`). Для автоматизации: `window.__ready`, `window.__shot(name)`, `window.__renderer`.
Скриншоты: `reports/screens/*.png` (SwiftShader, 1280×720, профиль W60 — картинка для визуальной оценки, не
замер скорости). Воспроизвести скриншоты и функциональные проверки контракта (потеря устройства, пауза, смена
профиля, отчёт маршрута, экран «нет WebGPU», ноль ошибок валидации):
`node web/build.mjs && node web/src/bench/render_checks.mjs --profile W60` → `reports/screens/screens.json`
(проверка HDR-кадра на NaN/Inf/чёрные пиксели) и `reports/screens/render_checks.json`
(`pass | fail | blocked | not_run`; производительность на RTX 3060 — `not_run`).

Замечание по инструменту: с флагом `--disable-vulkan-surface` (сейчас в `tools/chromium.mjs`) headless Chromium не
композитит WebGPU-canvas в скриншоты — получается белый кадр. Скриншоты сделаны с теми же флагами без него.

## Чего нет (сознательно)

* Нет перестройки GI и динамического непрямого света: статичный свет запечён (Документ §4, §5); ровер и экипаж
  получают запечённую видимость/AO рельефа в своей точке.
* Нет трассировки лучей, path tracing, mesh shaders, bindless — только базовый WGSL (Документ §5).
* Нет лиц, кожи и волос: экипаж в шлемах с визорами; лицевая анимация, hair cards и кожа — отдельная задача
  (Документ §4, §14).
* Нет TAA/temporal upscale (нет motion vectors) — честный пространственный апскейл; MSAA не используется (во всех
  профилях `msaa: 1`); режим AO `full` пока работает как `half`.
* Нет стриминга ассетов: вся сцена процедурная и готовится при загрузке; интерьеры модулей, кроме шлюза и ангара,
  не моделируются.
* Производительность на RTX 3060 не измерялась: нужен прогон маршрута на целевом ПК.
